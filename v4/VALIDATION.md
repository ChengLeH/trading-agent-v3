## 獨立審查與修復

程式先經重用／可讀性／效率檢查，再做 correctness（正確性）、adversarial（對抗）、testing（測試）與 reliability（可靠性）等獨立程式審查。
沒有使用外部跨模型命令列審查，也不聲稱測試替身代表真實模型語義驗收。

審查在 `ad2095c` 找到三項高優先問題，均以共用契約修復於 `9177586`：

1. 未完成角色的檢查點可跳進 Phase 6 並交付半份報告：現在執行與最終交付都要求完整九角色，半份檢查點會明確封鎖。
2. 唯一交易方案 Claim 可被改型、卻留下舊交易數值：現在初始提交、修補、重載與最終驗證共同要求唯一且一致的 trade_plan。
3. 逐步收集介面省略模型身分可繞過獨立審查：三層收集均要求非空模型身分，深度審查與第一層必須不同；確認批次模型身分後才發布合格項紀錄，不合格項不發布。

主代理把新回歸測試放回匯出的 `ad2095c` 比較基準，重現 8 個失敗子案例；修復後全數通過。
另外新增命令列輸出新鮮度保證：輸入／檢查點載入失敗也覆蓋舊成功結果；若無法寫入結果，明確輸出 `result_written=false`。這是額外強化，不將它混稱為上述三項根因。

## Antigravity 與中途保存修正

先前內建 Gemini direct API（直接 API）不是使用者原有接法；V4 改為全部使用 Antigravity `agy`。失敗不轉接 API，不讀 API 金鑰；保留既有登入、環境代理與呼叫者明選的模型。`092ea40` 的直接 API 代理修正已由此路徑取代。
測試涵蓋缺 CLI、失敗、逾時、非 JSON、環境繼承、明確模型與執行檔，確認不使用 shell（命令殼層）或略過權限旗標；已實際執行 `agy --help` 與 `agy models` 成功，沒有執行模型推論。
原本 CLI 只在整段 execute 返回後才存檔。現在每階段保存 canonical checkpoint（正式狀態檢查點）、每筆回覆立即寫入輸出目錄，保留各次嘗試；新執行先使舊成功交付失效。
新增 11 項持久化測試，包括子程序於並行角色呼叫中 `os._exit(17)`、CLI 於呼叫中 `os._exit(19)`，確認檢查點及成功回覆保存、角色續跑與舊成功報告失效。另測模型／脈絡改變不可重播、明確重試角色、磁碟在呼叫前／回覆後失敗、交易保存失敗回滾，以及語義驗證仍全數重新呼叫。
持久化與 Antigravity 連線經 GPT-6 Luna／Max 獨立審查；依其建議補上指定角色重試、CLI 硬中止與回覆落盤失敗案例。另修正封存成功但索引未更新的中斷窗口，以 attempt_id（每次呼叫識別碼）恢復當次已保存回覆，並測明確重試中斷後不能回播舊目錄的答案。

## VM 修復同步：長文 stdin 與空回覆重試

使用者提供 VM 已驗證的修復片段；GitHub 的 `acca73a` 尚未包含兩項行為。先補反例重現長文沒有送進 stdin，以及缺少空回覆重試，再修改共用的 `AntigravityCloudClient`。
超過 64 KiB UTF-8 的 prompt 走官方 `stream-json` stdin 協定，保留完整內容、長文單次逾時至少 1800 秒；短文保留既有路徑。兩條路徑保留原權限限制，未加入 VM 片段內的略過權限旗標。串流拒絕缺失、重複、失敗或無字串回覆的終端結果，不曝光原始錯誤內容。
依使用者最後提供的程式，總共 3 次（首次＋2 次），間隔 15 秒；空字串、純空白與呼叫例外可重試，非空但非法 JSON 仍直接封鎖。
新增 7 項傳輸回歸：真實替身子程序收到 189000 位元組、內容雜湊相同且參數保持短小；UTF-8 邊界與長文逾時；空回覆／例外恢復；次數上限；非法 JSON；串流結果完整性。測試替換等待與雲端呼叫，沒有真實模型推論。VM 的先前成功屬使用者提供的驗證證據，本次未重跑該 VM。
此輪經 GPT-6 Luna／Max 獨立檢查；依其建議，將長文的 CLI `--print-timeout` 與外層 subprocess timeout（程序等待上限）都明確設成相同值，不依賴各 CLI 版本的預設值。

## 缺少逐引用欄位的受控恢復

使用者回報 VM 中 87 個 atomic（原子驗證）結果命中舊快取，只有 claim_id／verdict／findings，整理時被嚴格 validator（驗收器）拒絕。保留 `normalize_reference_checks` 的必要欄位與語義一致性檢查；不使用缺值預設 `[]`、不在收集時假造來源支持紀錄。
先加入反例，在 `2c4a49d` 重現收集拋例外、87 筆流程封鎖、沒有逐條重驗上限／狀態；再補每條 Claim 的結構化回覆規格（必要欄位、Claim／引用 ID、筆數）、Antigravity `--json-schema`、契約版本與驗證請求識別碼。
結果收集改為逐條分隔合格與不合格項，保存合格項／檢查點，回傳結構化重驗計畫；內建流程只重驗不合格／漏回項，最多 3 次契約嘗試，仍失敗就封鎖。合法 JSON 但缺欄位與連線層錯誤分開處理，非空但非法 JSON 不會被猜修。
新增 9 項測試：87 筆舊格式快取各自取得完整新語義結果後才能交付；部分成功持久化、只重驗失敗項、重試用盡不進深審／全局、舊 PASS 重驗改判 FAIL 後必須深審與修補、修補後後代重驗、來源過期拒收、實際保存／重載檢查點後原子與深審提示更新、每 Claim 規格與雜湊傳遞、兩種 CLI 傳輸都帶規格，以及過大規格在啟動前拒絕。
既有漏引用、重複／未知引用、矛盾／證據不足卻 PASS 的回歸保留，並增強為：獨立正規化器仍拋驗收錯誤，收集器回 blocked 且不保存該 Claim 收據、不允許全局交付；不再要求整批收據都丟失。
此輪由 GPT-6 Luna／Max 獨立檢查，依其意見補上新執行的驗證識別碼，並明列重試預算只限本次 runner、重載後重驗與重新計數。每個回覆規格由副本產生，不把共用 schema（結構描述）字典交給自訂客戶端修改。
測試使用腳本結果，沒有真實雲端推論，也沒有讀取 VM 的 87 筆實際快取或改動其自訂 driver。使用者回報的 `driver_exit rc=9` 未在該 VM 重跑；內建執行流程已通過等價的舊格式回覆恢復案例，自訂 driver 必須採用新的重驗計畫與規格介面。

## 尚未驗證與限制

- 依使用者決定，本次先交付程式與測試，真實雲端模型驗收另行安排。語義品質、實際延遲、費用、模型可用性與真實市場資料結果均未驗證。
- V3 依賴外部 `/tmp/amzn_v3.json` 的資料驗收未執行；本環境沒有該測試資料。上述兩組 V3 回歸已實際執行。
- V4 新 renderer（報告產生器）依角色與明確 subsection 產生報告，未複製 V3 固定十二章版型。
- 大型角色證據包仍可能需要結構化來源選取或分頁；不以文字快篩或截掉正式 Claim 解決。
- 未支援的 Calc 操作會留下 WARN（警告），不宣稱已有程式重算證明；LLM 仍必須審查每條有效 Claim。
- 檢查點重載後會補齊未完成角色；全部 Claim 與全局一致性重新驗證，因此會再產生雲端用量。非完整批次或階段次序錯亂的人工檢查點仍須由有效檢查點或 manifest 重跑。
- 僅驗證程序中止與重新載入；不宣稱 VM 被銷毀、磁碟遺失或權限外的暫存目錄清除後仍能恢復。必須使用持久化輸出磁碟。進行中的雲端請求可能於續跑重送；長文已改走 stdin，但模型本身的脈絡容量限制仍存在。
